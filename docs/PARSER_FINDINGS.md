# Parser and safety findings

Tests read the documented rules and source first, use the fixture catalogue or synthetic **dev** data, and never read or change the locked synthetic test cases. All examples below use synthetic product data.

The first `/opt/homebrew/bin/node --test test/parse-more.test.ts test/rules.test.ts` run produced **47 tests, 36 passed, 11 failed**, in **138.56 ms**, before source changes. The repeated captured run is in `test/evidence/parser-before.txt`. An additional price-as-quantity test failed after the initial fixes: **50 tests, 49 passed, 1 failed**, **186.47 ms** (`parser-second-before.txt`). Baseline-module reproductions are recorded in `test/evidence/parser-baseline-reproductions.jsonl`, using the untouched source snapshot.

After all parser fixes, the focused parser, property and validation command produced **77 tests, 77 passed, 0 failed**, **225.25 ms** (`test/evidence/parser-after.txt`). This is a focused command, not a claim about the final complete suite. An earlier complete suite run passed **142/142** in **3.116 seconds** (`test/evidence/parser-full-suite-check.txt`); subsequent regressions were added afterwards, so the main testing report contains the final complete-suite result.

“Validator boundary” means a direct `finalize()` proposal bypass; the current production model path copies quantity/unit from the parser, so those particular model-supplied values cannot originate from Ollama today. They are still violations of the documented finalizer rules and now have defensive regressions. The other parser and conflicting-hint failures reach normal deterministic proposals.

Independent review then exposed P12. Its separate fail-before run is `test/evidence/parser-extra-unknown-before.txt`: **51 tests, 49 passed, 2 failed, 130.61 ms**, including a full deterministic `exact`/`fuzzy` method-path regression. The fix applies the existing bare-number/unknown-word detection even when another known pair has already been found. An extra unmarked number alone is still not guessed as a price or unit.

The final independent review exposed P13. Its separate fail-before run is `test/evidence/parser-overlapping-price-before.txt` (**52 tests, 50 passed, 2 failed**). The fix permits a shared currency marker to retain the second price in `rs 5 rs 10`, while tests ensure ordinary `5 rs 2 pkt` and `5 rs 2` still retain quantity 2.

Minimal fixes are limited to preserving information in `normalize()/parse()` and enforcing existing finalizer rules: preserve negative signs and decimal punctuation, recognise `rs.10`, map the two requested additional digit ranges, retain all explicit price/size hints, compare full number+unit pairs against product aliases, and make unknown-unit/missing-quantity checks independent of proposal guesses. `src/types.ts` adds optional arrays for complete price/size hints without changing existing callers. `docs/RULES.md` describes these exact changes. No retrieval thresholds, aliases, gold labels, or dependencies changed.

Suspected cases refuted by executable tests: distinct `maggi 2 ctn 5 pkt` with the ordinary parser proposal already requires review; Dettol soap grams cannot accept a millilitre size; `maggi bhej dena` and `ek petti frooti` remain item rows, while a greeting is a note. Full-width digits and a zero-width separator between number and unit work. A later numeric-format review exposed P11: its separate fail-before run is `test/evidence/parser-zero-width-before.txt` (23 tests, 22 passed, 1 failed), followed by the numeric-only format-mark fix. Word shaping and ordinary word boundaries are preserved. The new seeded properties run on **320 dev lines plus 1,200 generated mutations**, using `mulberry32(20261013)`; both accepted and rejected finalizer results are exercised.

Debatable cases are explicitly characterised, without guessing intent: `half kilo` is not in the documented number vocabulary and remains literal product text; an unmarked `14` in `maggi 14 2 ctn` is not inferred to be a price. Hindi `do` away from a unit is not counted as a quantity. Supporting every numeral script and every informal pack-size expression was not attempted.

Real Ollama behaviour, browser interactions, and the adversarial hybrid identity invariant are covered elsewhere or listed as limitations in the main testing report; these focused tests use no network or real model.
