What each metric means

Metric definitions used by the evaluation harness
MetricDefinition
Handled with no reviewCorrect automatic rows ÷ answerable lines. Product, quantity and unit must all be right (“auto-accept accuracy”).
Dangerous rowsWrong automatic rows + missed review flags. Rate: divide by all lines. Target: zero.
No typing neededCorrect automatic rows + fully correct flagged suggestions, divided by answerable lines (“zero typing”).
Suggestion accuracyFully correct suggestions ÷ flagged answerable rows.
Flag recallCorrectly flagged rows ÷ all lines needing review.
Review loadRows sent to the operator ÷ all lines.
Recall@kCorrect product inside the k model candidates.
Model calls and latencyCall count and p50 / p95 model response times.

A boundary around the test

Lock first. Tune on practice data.

  1. Label what a careful operator would conclude.
  2. Hash-lock the test before any model runs. Changed locked sets cannot be scored.
  3. Tune prompts, thresholds, aliases and parser words only on development data.
  4. Compare methods on the same locked test. Justify fixes using development examples.

The synthetic test uses a separate seed; near-duplicate practice lines are rejected and leak-checked. Both reflect one author’s assumptions.

What remains unknown

Real orders are the next test

  • Synthetic data only; no real shop use yet. Real review rates are unknown.
  • Prices, carton sizes and nicknames are illustrative.
  • One shop, operator and order at a time. Pasted text only; no photos, voice or WhatsApp integration.
  • A comma inside an item’s description, such as maggi, 4 pack 1 ctn, splits it into two rows. Commas inside numbers (1,500) are read correctly.
  • No local-server authentication; a single-user desktop tool.
