How it works

Code reads the numbers.
The model picks a product.

A clear match becomes a ready row. An uncertain match becomes one short question, with a suggestion when available.

From slip to ledger

A small, deliberate pipeline

  1. Parse

    Code reads quantity, unit, price and pack size, normalising supported digits and spellings.

  2. Match the text

    Fuzzy matching needs a score ≥ 0.5 and a lead ≥ 0.08 over the next candidate.

  3. Ask the model if needed

    If fuzzy cannot name the product, the local model picks from the top 8 candidates or abstains.

  4. Check every pick

    All 15 rules must pass for Ready. Otherwise the row is Needs you.

Greetings and notes can become grey, ignored rows. “Treat as item” overrides this.

A boundary learned by testing

The model never owns a number

In the first trial, the model changed petti (carton) to packet in 3 of 4 lines, despite the prompt’s definition.

Now code supplies every number. The model returns only product evidence, a catalogue SKU and a status.

The governing rule

A wrong row must never be auto-accepted. When unsure, ask one short question.

Model and text picks face the same checks.

Source: Design D2–D5. Trial on synthetic development examples, not shop orders.

Remember a name, keep the checks
